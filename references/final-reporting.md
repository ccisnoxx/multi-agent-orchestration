# 子代理执行摘要与最终报告

## 触发条件

只有至少一个子代理创建操作实际成功时，才生成 `SUBAGENT_EXECUTION_DIGEST` 和用户可见的“子任务执行概览”。

仅计划使用子代理、尝试创建但失败、读取代理配置或审查本 Skill，不算实际使用子代理。

## 可信来源

执行摘要只能来自本机审计工具对本次任务记录的校验和聚合结果。

生成最终报告前，确认：

- digest 属于当前根任务；
- digest 覆盖最新一轮执行记录；
- 审计工具校验成功；
- 所需字段完整；
- 没有把历史任务记录混入当前任务；
- 没有仍未归档但会改变统计的执行记录。

未满足这些条件时，不生成或推算统计，只报告审计不可用及其影响。

## 状态与验收语义

- “执行尝试数”按审计工具定义的实际执行尝试计数。
- “验收通过数”只能统计执行记录中 `task_outcome=accepted` 的记录。
- `final_status` 只表示 Worker 或线程运行时状态，不表示任务验收结果。
- `completed`、`finished`、`success` 或类似运行时状态不得改写为“验收通过”。
- `rejected`、`role_mismatch`、`not_evaluated`、`cancelled` 和其他未验收结果，不计入验收通过。
- “独立复核数”只能按审计工具明确认定的独立只读复核记录统计；主代理自查不算独立复核。
- 不清楚的计数标记为未知，不使用零代替未知。

## Agent 配置

默认按 `agent_type` 聚合。

同一 `agent_type` 存在不同 Agent TOML 配置时，按配置组合分别展示，不得合并后只显示其中一种配置。

模型和推理档位只有在 Agent TOML 中显式配置时，才标注为“Agent TOML 配置”。

未显式配置时写“未显式配置”，不得用继承值、推断值或当前主代理设置冒充 Agent TOML 配置。

只有运行时接口直接返回模型或推理档位，并且审计工具将其标记为可验证运行时数据时，才可以另外标注为“运行时确认”。

## 正常聚合字段

正常情况下，概览只展示：

- `agent_type`；
- Agent TOML 中显式配置的模型和推理档位；
- 执行尝试数；
- 验收通过数；
- 独立复核数；
- 计划校验结果；
- 未执行的 ready task；
- 残留活跃 Worker；
- 写入证据状态。

不展示：

- 完整 `worker_id`；
- 完整 `runtime_ref`；
- 命令数组；
- 绝对路径；
- 完整波次；
- 空数组；
- 重复的正常布尔字段；
- 完整 `WORKPLAN_EXECUTION_SUMMARY`；
- 原始机器审计记录。

## 异常展示

存在以下情况时，在概览末尾增加简短的异常说明：

- `role_mismatch`；
- `rejected`；
- `not_evaluated`；
- 未执行 ready task；
- 残留活跃 Worker；
- 未知写入证据；
- digest 校验不完整；
- Agent 配置冲突；
- 其他未验收通过结果。

只列与结果或风险有关的异常，不展示无关原始字段。

## 用户可见格式

多个 `agent_type` 时可以使用简短表格：

| Agent 类型 | Agent TOML 配置 | 尝试 | 验收通过 | 独立复核 |
|---|---|---:|---:|---:|
| `reviewer` | `model=...`, `effort=...` | 2 | 1 | 1 |

随后根据 digest 简述：

- 计划校验；
- 未执行 ready task；
- 残留活跃 Worker；
- 写入证据；
- 仅在存在时列出的异常。

只有一个 `agent_type` 且字段较少时，优先使用一至两个自然段，不为了形式创建表格。

## 审计不可用

实际使用了子代理，但没有取得有效 digest 时，使用以下语义：

“本轮使用了子代理，但未取得属于当前任务且校验通过的执行摘要，因此无法可靠报告执行尝试数、验收通过数、独立复核数和写入证据。”

不得自行补充估算数字。

## 严格机器可读输出

用户要求严格 schema 时：

- 不在 schema 外追加 Markdown 章节；
- schema 包含审计字段时，按 schema 填写；
- schema 不包含审计字段时，将审计记录保留在约定日志或旁路文件中；
- 不擅自添加新字段。
